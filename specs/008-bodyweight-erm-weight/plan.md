# Implementation Plan: Persisted eRM & Optional Weight Entry

**Branch**: `008-bodyweight-erm-weight` | **Date**: 2026-05-31 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/008-bodyweight-erm-weight/spec.md`

## Summary

Allow bodyweight and assisted exercises to be logged with empty or zero weight (using the user's recorded body weight as the effective load), and compute + store eRM at save time so historical values are not affected by future body weight changes. Builds on the classification model and Settings page introduced in 007-erm-bodyweight.

**Constraints**: COOP/COEP headers required; no backend; OPFS-only persistence  
**Scale/Scope**: Single user, single browser origin

## Key Design Decisions (summary)

See `research.md` for full rationale.

- **eRM persisted, not computed at display time** — historical accuracy when body weight changes
- **weight column made nullable** — null = empty field (no added weight); 0 = explicit zero
- **eRM computed in form layer, passed to DB helper** — DB helpers remain pure storage
- **No backfill of pre-existing sets** — body weight at original log time unknown; null eRM is honest
- **No schema change to routine_exercise** — the form's runtime filter is the only fix needed for routines
