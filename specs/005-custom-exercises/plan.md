# Implementation Plan: Custom Exercise Library

**Branch**: `005-custom-exercises` | **Date**: 2026-05-27 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/005-custom-exercises/spec.md`

## Summary

Add an exercise library to the workout PWA: 24 pre-seeded exercises (each tagged with one or more muscle groups from a managed list of 12), full CRUD on both entities, an exercise picker (MUI Autocomplete) wired into WorkoutForm and RoutineEditor, and a dedicated Exercise Library screen as a third top-level tab. All data lives in three new SQLite tables introduced via a Drizzle migration.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)  
**Primary Dependencies**: React 18, MUI v6, Drizzle ORM, SQLite-WASM (sqlite3Worker1Promiser)  
**Storage**: SQLite via OPFS (WASM worker), in-memory fallback  
**Testing**: None configured (Constitution Principle V)  
**Target Platform**: PWA — modern mobile and desktop browsers (cross-origin isolated context required)  
**Project Type**: Local-first browser PWA  
**Performance Goals**: Exercise list loads in <200ms; picker filters in <100ms (all local, no network)  
**Constraints**: Offline-capable, no backend, single DB worker, OPFS requires COOP/COEP headers  
**Scale/Scope**: ~24–100 exercises, ~12–30 muscle groups per user

## Constitution Check

| Principle | Status | Notes |

| IV. Parameterised SQL Only | PASS | All raw promiser calls use `bind: [...]`; Drizzle ORM handles the rest |

| VI. Mobile-First | PASS | MUI Autocomplete + 44×44px touch targets; must verify at 320px |
| VII. Component Separation | PASS | `ExerciseLibrary` = container; all form/list components = presentational |
| VIII. File Size | PASS | Each new file planned to stay under ~200 lines |
| IX. Strong TypeScript Types | PASS | No `any`, no `as unknown as X`; Drizzle inference used for row types |
