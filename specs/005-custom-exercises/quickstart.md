# Quickstart: Custom Exercise Library

## What this feature adds

1. **Three new DB tables**: `exercise`, `muscle_group`, `exercise_muscle_group` (seeded with 24 exercises and 12 muscle groups).
2. **Exercise Library screen**: third top-level tab with sub-tabs for Exercises and Muscle Groups. Full CRUD on both.
3. **Exercise picker in WorkoutForm and RoutineEditor**: plain TextField replaced by MUI Autocomplete loaded from the exercise library.

## Implementation order

1. **Schema + migration** — add tables to `schema.ts`, run `npx drizzle-kit generate`, verify migration SQL includes seed INSERT statements.
2. **`exerciseHelpers.ts`** — implement all helpers per `contracts/database.ts.md`.
3. **Re-export barrel** — update `src/database.ts`.
4. **`ExercisePicker`** — build the Autocomplete wrapper; verify it loads and filters.
5. **Swap picker in WorkoutForm** — replace the exercise name `TextField`.
6. **Swap picker in RoutineEditor** — replace the exercise name `TextField` in the dialog.
7. **Exercise Library screen** — build container + sub-components; wire CRUD.
8. **Add tab to App.tsx** — expose the Exercises tab.

## Constitution compliance notes

- **Principle III**: All DDL is in the Drizzle migration file. Seed data is `INSERT OR IGNORE INTO` in the same migration. No inline DDL in `initDatabase`.
- **Principle IV**: All SQL uses `?` placeholders; no string interpolation.
- **Principle II**: No new promiser calls outside `exerciseHelpers.ts` / Drizzle ORM. All helpers call `initDatabase()` at the top.
- **Principle VII**: `ExerciseLibrary` is a container; `ExerciseList`, `ExerciseForm`, `MuscleGroupList`, `MuscleGroupForm`, `ExercisePicker` are presentational.
- **Principle VIII**: All new files stay under ~200 lines. If `ExerciseLibrary.tsx` grows beyond that, extract sub-state into a custom hook (`useExerciseLibrary`).
- **Principle VI**: `ExercisePicker` Autocomplete must have a minimum touch target of 44×44px; all interactive elements in list rows must meet the same target.

## Key runtime behaviour

- **Picker data load**: `ExercisePicker` accepts an `exercises: Exercise[]` prop loaded by its parent container (not self-fetching). This keeps the component presentational and avoids redundant DB calls when multiple pickers appear on screen simultaneously.
- **Rename propagation**: `updateExercise` wraps four statements in one transaction. If the transaction fails, no partial rename is visible.
- **Delete + routine slots**: `deleteExercise` fetches the exercise name first (to match `routine_exercise.exercise_name`), then deletes in one transaction. The cascading `exercise_muscle_group` rows are handled automatically by SQLite's FK cascade.
- **Muscle group delete + exercises**: After `deleteMuscleGroup`, exercises with zero remaining groups are left in the library. The UI should display these with a warning badge and block saving until at least one group is re-assigned (only applies to subsequent edits; the delete itself is not blocked).
