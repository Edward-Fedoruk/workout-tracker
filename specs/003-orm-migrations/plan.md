# Implementation Plan: Drizzle ORM with Database Migrations

**Branch**: `003-orm-migrations` | **Date**: 2026-05-23 | **Spec**: `specs/003-orm-migrations/spec.md`

## Summary

Integrate Drizzle ORM (`drizzle-orm/sqlite-proxy`) with the existing `@sqlite.org/sqlite-wasm` worker and add a startup migration runner. The ORM wraps the existing promiser with a typed query builder; migration SQL files are generated by Drizzle Kit and bundled into the Vite build via `import.meta.glob`. All existing query helpers are rewritten using Drizzle's API while preserving identical external signatures.

## Technical Context

**Language/Version**: TypeScript 5.5, React 18.3  
**Primary Dependencies**: `drizzle-orm` 0.45.x (new), `drizzle-kit` 0.31.x (new dev dep), `@sqlite.org/sqlite-wasm` 3.46.x (existing), Vite 5.4, MUI 9  
**Storage**: SQLite-WASM via OPFS (existing); no new persistence layer  
**Testing**: None — per Principle V, no test runner is configured  
**Target Platform**: Browser (cross-origin-isolated, OPFS VFS)  
**Project Type**: Local-first PWA  
**Performance Goals**: Migrations complete within 1 second of app startup (SC-002)  
**Constraints**: Single worker, single dbId (Principle II); additive-only schema changes (Principle III); no SQL string interpolation (Principle IV); files ≤200 lines (Principle VIII)  
**Scale/Scope**: One SQLite file per browser origin; single concurrent user; 3 existing tables + 1 migration-tracking table

## Complexity Tracking

> No constitution violations requiring justification.

One intentional deviation from FR-004 ("all queries MUST use Drizzle ORM"):

| Deviation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| `listWorkouts` pivot query uses raw promiser exec | Drizzle query builder cannot express `MAX(CASE WHEN set_number = N ...)` pivot pattern without a subquery workaround that would be harder to read and maintain | Fetching all sets and pivoting in JS is viable (see contracts/database.ts.md) but changes the query shape; deferred to implementer judgment with both approaches documented |
| `exportDatabaseBytes` / `replaceDatabaseAndReload` use raw promiser `export`/`close` commands | These operate on the binary database file, not on rows; there is no Drizzle equivalent | N/A — these are file-level operations, not SQL queries |
