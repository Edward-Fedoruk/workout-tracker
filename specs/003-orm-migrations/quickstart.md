# Quickstart: Adding a Database Migration

**Branch**: `003-orm-migrations`

This guide explains how a developer adds a new database schema change after this feature is implemented.

---

## Prerequisites

- `drizzle-kit` installed as a dev dependency
- `drizzle.config.ts` at the project root pointing to `src/db/schema.ts` and `drizzle/` output

---

## Step 1: Modify the Drizzle schema

Edit `src/db/schema.ts`. For example, to add a `notes` column to `workout_log`:

```ts
export const workoutLog = sqliteTable('workout_log', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  workoutDate: text('workout_date').notNull(),
  exerciseName: text('exercise_name').notNull(),
  notes: text('notes'),              // ← add this
  createdAt: text('created_at').default(sql`CURRENT_TIMESTAMP`),
  updatedAt: text('updated_at').default(sql`CURRENT_TIMESTAMP`),
});
```

---

## Step 2: Generate the migration file

```bash
npx drizzle-kit generate
```

Drizzle Kit diffs the current schema snapshot against the new schema and writes a new SQL file:

```
drizzle/
├── 0001_init.sql
├── 0002_add_notes_column.sql    ← new file
└── meta/
    ├── _journal.json
    └── 0002_snapshot.json
```

Review the generated SQL to confirm it is additive (no DROP COLUMN, no destructive changes).

---

## Step 3: Start the app — migration runs automatically

```bash
npm run dev
```

On startup, `initDatabase()` runs the migration runner, which:
1. Reads `__drizzle_migrations` to find applied migrations
2. Detects `0002_add_notes_column.sql` as pending
3. Executes it and records it as applied
4. Validates the schema (checks `notes` column now present in `workout_log`)

No manual SQL execution required.

---

## Step 4: Update query helpers

If the new column should be read/written, update the relevant helpers in `src/database.ts`:

```ts
export async function createWorkout(
  workoutDate: string,
  exerciseName: string,
  sets: Array<{ weight: number; reps: number }>,
  notes?: string,       // ← add optional param
): Promise<number> {
  // ...
}
```

---

## Rollback (development only)

If the migration introduced an error during development, roll it back in the browser console:

```js
// DevTools console (only works in npm run dev)
await __devRollback('0002_add_notes_column.sql');
```

This executes the corresponding down-migration and removes the record from `__drizzle_migrations`. After rollback, revert your `src/db/schema.ts` change and regenerate.

---

## Migration error during startup

If a migration fails (syntax error, constraint violation), the app shows an error modal with two options:

- **Retry** — fix the migration SQL and reload
- **Reset database** — wipes the OPFS database and starts fresh (data loss; use only as last resort in dev)

---

## Key files at a glance

| File | Purpose |
|------|---------|
| `src/db/schema.ts` | Edit to change schema |
| `drizzle/*.sql` | Generated by Drizzle Kit; commit these |
| `drizzle/meta/` | Drizzle Kit tooling state; commit these |
| `drizzle.config.ts` | Drizzle Kit config |
| `src/db/migrations.ts` | Runtime migration runner (do not edit for routine migrations) |
| `src/database.ts` | Public query helpers |
