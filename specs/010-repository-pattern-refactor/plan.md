# Implementation Plan: Database Repository Pattern Refactor & Component Cleanup

**Branch**: `010-repository-pattern-refactor` | **Date**: 2026-06-01 | **Spec**: [spec.md](spec.md)

## Summary

Reorganise the database layer by splitting the monolithic `src/db/schema.ts` and scattered helper files into per-entity subdirectories under `src/db/entities/`, each containing a `schema.ts`, `repository.ts`, and `types.ts`. Repository classes reference the module-level Drizzle `database` object directly; `src/database.ts` remains the single barrel that calls `initDatabase()` and re-exports the full public API for component consumption. Simultaneously: collapse the `'assisted'` classification into `'bodyweight'`; replace every `last_insert_rowid` pattern with Drizzle's `.returning()`; and refactor all React components to the `create-component` scaffold conventions.

## Technical Context

**Language/Version**: TypeScript 5.x, Node 22 (build host)
**Primary Dependencies**: React 18, Drizzle ORM (sqlite-proxy), @sqlite.org/sqlite-wasm, Vite 6, MUI v9
**Storage**: SQLite-WASM → OPFS (primary), in-memory fallback
**Testing**: None configured (per constitution Principle V — do not add ad-hoc)
**Target Platform**: Browser (WASM + OPFS; requires cross-origin isolation)
**Project Type**: Local-first PWA
**Performance Goals**: All DB calls async over the promiser; no synchronous escape hatch
**Constraints**: Cross-origin isolated context required; single Web Worker; no backend
**Scale/Scope**: Single-user, single-origin SQLite DB; ~7 entities; ~25 React component files
