# Implementation Plan: Shared UI Component Library & URL Routing

**Branch**: `009-ui-component-library` | **Date**: 2026-05-31 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `specs/009-ui-component-library/spec.md`

## Summary

Extract reusable presentational dialog and button components into `src/components/ui/` (eliminating duplicated MUI boilerplate across 6 existing dialogs), then replace the custom `ActiveView` state-machine in `App.tsx` with `react-router-dom` v6 URL-based routing — giving the app real browser history, deep linking, and bookmarkable URLs.

## Key Design Decisions

- **`ConfirmDialog` vs custom button slots**: `MigrationErrorDialog` needs two custom action buttons (Retry + Reset Database), not the standard cancel/confirm pair. `ConfirmDialog` handles this by making `onCancel` optional — when absent, the cancel button is hidden and the `children` slot can contain arbitrary action content. This avoids a special-case `actions` prop.

- **`AppLayout` owns `initDatabase()`**: The DB init call moves from `App.tsx` to `AppLayout.tsx`. `App.tsx` becomes a pure composition root (theme + router). `AppLayout` is a layout route component that gates on DB readiness before rendering `<Outlet />`.

- **Tab bar in `AppLayout`**: The tab bar is rendered by `AppLayout`, not by each route. Its `value` is derived from `useLocation().pathname` via `pathnameToTabValue()`. This keeps the tab bar as a single source of truth driven entirely by the URL.

- **`RoutineEditor` create vs. edit mode**: The `/routines/new` route renders `RoutineEditor` with no `:id` param. The component checks `useParams().id === undefined` to determine create mode. This avoids a separate `NewRoutineEditor` component.
