# Implementation Plan: Routine Draft Persistence

**Branch**: `011-routine-draft-persistence` | **Date**: 2026-06-08 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/011-routine-draft-persistence/spec.md`

## Summary

Auto-save the in-progress routine workout form to a new singleton SQLite table (`routine_workout_draft`) on every form change. On resume — whether after a page reload or a within-session tab switch — restore saved set values into the form. Surface a dot badge on the Routines tab icon and an "In Progress" indicator on the relevant routine card. Provide an explicit two-tap Discard flow inside the form. Cascade-delete the draft when its parent routine is deleted.

## Technical Context

**Language/Version**: TypeScript 5.x / React 18  
**Primary Dependencies**: Vite, MUI v5, React Hook Form, Zod, Drizzle ORM, `@sqlite.org/sqlite-wasm`  
**Storage**: SQLite-WASM via OPFS (Drizzle ORM); in-memory fallback when OPFS unavailable  
**Testing**: None configured (Principle V — do not add ad-hoc)  
**Target Platform**: Browser PWA, mobile-first (≥320 px)  
**Project Type**: Local-first single-page web application  
**Performance Goals**: Draft write latency imperceptible to user (debounced 500 ms; single-row upsert)  
**Constraints**: No second persistence layer; no server; must comply with all nine constitution principles  
**Scale/Scope**: Single user, single device; at most one draft row in the DB at any time
