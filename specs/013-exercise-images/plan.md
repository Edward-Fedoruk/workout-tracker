# Implementation Plan: Exercise Images (illustrated exercise library)

**Branch**: `013-exercise-images` | **Date**: 2026-06-11 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/013-exercise-images/spec.md`

## Summary

Add a bundled image library (1,324 `.jpg` files from `hasaneyldrm/exercises-dataset`) to the app. Each exercise gains a nullable `image_filename` column. The Exercise Library list renders a circular avatar per row using MUI `Avatar`. A new `ExerciseImagePicker` modal lets users search and select an image when creating or editing an exercise. All 24 default exercises are pre-matched via a Drizzle migration UPDATE. See `research.md` for all key design decisions.

## Technical Context

**Language/Version**: TypeScript 5 / React 18  
**Primary Dependencies**: Vite + vite-plugin-pwa, MUI v5, Drizzle ORM, SQLite-WASM, Zod, React Hook Form  
**Storage**: SQLite-WASM → OPFS (primary), in-memory fallback; static `.jpg` assets in `public/exercises/`  
**Testing**: None configured (per constitution Principle V)  
**Target Platform**: Browser PWA (mobile-first, offline-capable)  
**Performance Goals**: Image picker search responsive < 100ms; exercise list renders without jank  
**Constraints**: Offline-capable (all images cached), no backend, no second persistence layer  
**Scale/Scope**: 1,324 bundled images, 24 pre-matched default exercises

| Principle | Status | Notes |
|---|---|---|
| I. Local-First | ✅ Pass | Images are static build assets; no remote fetch at runtime |
| II. Single Worker / Single Init | ✅ Pass | All DB access via repository; no new worker |
| III. Schema-Complete Before Ready | ✅ Pass | Drizzle migration workflow: schema → `drizzle-kit generate` → `.sql` file |

| V. Simplicity & Explicit Scope | ✅ Pass | No test runner; catalog JSON is a committed static asset; no sync layer |
| VI. Mobile-First | ✅ Pass | Avatar is 40px circle; picker grid responsive; touch targets ≥ 44px |
| VII. Separation of Concerns | ✅ Pass | `ExerciseImagePicker` is presentational; hook manages state |
| VIII. Code Organization | ✅ Pass | New component in own folder; `@/` alias throughout |
| IX. Strong TypeScript Types | ✅ Pass | `imageFilename: string | null` typed; no `any` |

**Complexity tracking**: one deviation noted — Workbox offline caching for `.jpg` uses runtime caching (`CacheFirst`) rather than precaching, because precaching 1,324 images makes the install manifest unreasonably large. Images are cached on first access. SC-004 is satisfied after first load (see research.md § Offline Caching).

## Complexity Tracking

| Deviation | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| Runtime `CacheFirst` caching for `.jpg` instead of Workbox precache | Precaching 1,324 images would make the SW manifest huge (potentially hundreds of MB) and cause every PWA update to re-download all images | Precaching is impractical at this scale; runtime caching satisfies offline-after-first-view which is acceptable for an image library |
